# Day 04: First CUDA Kernel

## Objective

Implement and document a baseline GPU vector-add kernel.

## Operation

For vectors `a` and `b`:

`out[i] = a[i] + b[i]`

The operation is intentionally simple. Its value is in exposing the CUDA execution model before introducing more complex kernels.

## Execution model

The kernel maps one output element to one CUDA thread.

```text
Grid
 ├── Block 0
 │    ├── Thread 0 -> out[0]
 │    ├── Thread 1 -> out[1]
 │    └── ...
 ├── Block 1
 │    └── ...
 └── ...
```

The global thread index is:

`i = blockIdx.x * blockDim.x + threadIdx.x`

A bounds check prevents threads beyond `n` from accessing memory.

The baseline uses 256 threads per block.

## Host workflow

```text
Host arrays
    |
    | cudaMalloc
    v
Device buffers
    |
    | cudaMemcpy H2D
    v
GPU kernel launch
    |
    | vector_add_kernel<<<blocks, 256>>>
    v
Device output
    |
    | cudaMemcpy D2H
    v
Host output
```

## Correctness coverage

The test harness exercises sizes that include:

- one element
- values below a block size
- exactly one block
- one element above a block boundary
- an irregular size
- one million elements

The boundary cases are important because the kernel must handle partial final blocks correctly.

## Build

Requirements:

- NVIDIA GPU
- CUDA Toolkit
- CMake 3.18 or newer
- C++17 compiler

Build from this directory:

```bash
cmake -S . -B build
cmake --build build -j
./build/vector_add_test
```

## Performance measurement plan

The first benchmark should measure three quantities separately:

1. Host-to-device transfer
2. Kernel execution
3. Device-to-host transfer

For this operation, transfer cost is expected to matter because the arithmetic intensity is low. A benchmark that reports only total wall-clock time hides the distinction between computation and data movement.

CUDA events should be used for GPU-side timing in the next increment.

## Engineering observations

Vector addition exposes a basic GPU pattern: large amounts of independent work mapped across many threads.

It also introduces a central systems issue for ML workloads: moving data between host and device has a cost that is independent of the arithmetic operation itself.

The baseline kernel is intentionally unsophisticated. Optimization starts only after its behavior is measured.
