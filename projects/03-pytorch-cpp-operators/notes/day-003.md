# Day 3: Python to C++ Operator Boundary

## Objective

Start Project 03 by implementing a minimal native CPU operator and defining the contract it must satisfy.

## Operator

`lowlevel_ops.vector_add(a, b)`

For supported contiguous float32 CPU tensors:

`out[i] = a[i] + b[i]`

## Execution path

```text
Python
  |
  v
PyTorch operator namespace
  |
  v
lowlevel_ops::vector_add
  |
  v
CPU pointers
  |
  v
output tensor
```

The C++ implementation validates device, dtype, shape, and contiguity before accessing raw pointers.

## Why the restrictions are intentional

A first native kernel should expose the mechanics rather than hide them behind a large abstraction. Requiring CPU, float32, matching shapes, and contiguous storage makes the memory access pattern explicit.

Later stages will relax these constraints through dispatch and additional kernels.

## Important distinction

The C++ function does not receive a Python list. It receives a PyTorch tensor object containing metadata and access to tensor storage. The kernel then obtains typed pointers and iterates over elements.

This connects directly to Project 01's work on shape, strides, and storage, and Project 02's work on computation graphs.
