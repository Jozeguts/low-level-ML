# Day 05: GPU Memory and Performance

## Objective

Start Project 05 with a controlled block-size experiment for vector addition.

## Experiment

The same kernel and input size run with block sizes:

`32, 64, 128, 256, 512, 1024`

Only the block size changes. This isolates launch configuration as the experimental variable.

## Workload

- 16,777,216 float32 elements
- 2 input arrays
- 1 output array
- 10 warm-up launches
- 100 measured launches per configuration

## Metrics

The program emits CSV rows containing:

- threads per block
- block count
- average kernel time in milliseconds
- estimated effective bandwidth in GB/s

The bandwidth estimate counts two reads and one write per element.

## Why this experiment matters

Block size affects the number of blocks launched and the number of resident threads. It interacts with hardware limits such as maximum threads per block, register usage, shared-memory usage, occupancy, and scheduling.

Vector addition uses no shared memory and little arithmetic. This makes memory throughput and launch configuration useful first-order variables.

## Reproducibility

Build:

```bash
cmake -S . -B build
cmake --build build -j
```

Run:

```bash
./build/vector_add_bench > benchmark.csv
python analyze.py benchmark.csv
```

Actual benchmark numbers must be collected on the target NVIDIA GPU. The repository does not hard-code results.
